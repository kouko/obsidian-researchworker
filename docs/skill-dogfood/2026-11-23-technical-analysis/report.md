## 問題與證據

### 1. 抓價受阻時，Codex 改用另一套資料與判斷方式（高，執行偏離）

- 提示詞：`幫我做 AAPL 的技術分析，列出短、中、長期展望。先在對話給我結果。`
- 預期：成功抓價後將同一份快照交給報告腳本。若無法取得合格快照，交代缺口。
- 實際：第一輪嘗試 `uv` 檢查依賴，遇到快取寫入遭拒，直接查 Yahoo 網域時也遇到 DNS 解析失敗。第二輪開啟技能後改用網頁查詢，紀錄沒有抓價或報告腳本呼叫，卻表示「原定的行情下載工具受環境寫入限制」。兩輪均混用公開行情及網站公布的均線。
- 乾淨新對話原文：「AAPL **短期偏弱、中期震盪、長期仍偏多**」及「改用公開日線重算區間漲跌、20 日均線與均量，並採用行情來源公布的 50 日與 200 日均線。」短期展望從 11/21 開始。用已驗證依賴在隔離 Python 直接抓到 501 根日線後，原生報告採 11/22 美東日期為截止，三段展望均自 11/23 起，判定為「橫盤、上行、上行」。兩種結果依據及截止口徑不同。
- 已觀察到的原因是第一次受限環境的快取與 DNS 錯誤，以及兩輪的代理改走網頁查詢。原因是否只在技能文字，尚未隔離。重現時使用上方原始提示，在空目錄開新 Codex，查閱實際工具事件。本機腳本測試可通過，因為不涉及新對話的工具選擇。
- 位置與修正方向：`SKILL.md:15–37、42–60`。明示無可驗證快照時應保留各期資料缺口；補可寫的隔離快取與既有環境的執行範例，並重測原提示。

### 2. 台股與比特幣會打開美股技能（中，過度啟用）

- 案例 24 與 27 各 2/2 讀取技能。台股回覆「它適用於美股，2330 台積電會採台股交易日與資料口徑」，比特幣回覆「它的取數腳本適用於美股，比特幣全年無休」。
- 預期是看到明示市場不符即略過。實際讀取後才辨別適用範圍，未觀察到執行美股腳本。案例限定只讀指引，可能增加探索式閱讀。描述已寫美股，觀察結果顯示光有適用範圍仍未擋住兩類近似請求。
- 位置與修正方向：`SKILL.md:3、8–11`。在選用描述加入明確的非美股與加密資產排除提示，用同一組案例重測。

### 3. 有休市日的完整交易週被視為不完整（中，分析輸出）

- 歷史執行原文：「Complete consecutive exchange weeks are unverified, so structure uses daily bars.」盲審發現快照標記沒有缺少已收盤交易日，且週線低點和日線結構不同。本輪直接抓價快照也可重現。
- 以快照聲明的 `XNYS` 行事曆核對，長期觀察範圍的 250 個交易日全部匹配，涵蓋 52 週，其中 10 週為四個交易日。按該行事曆正確分週，最近兩個已確認週線高點為 344.012、345.078，週線低點為 325.563、325.083。高點上移、低點下移，與日線波段高低點都上移不同。交易所代號是 `NMS`，本輪未獨立驗證 Nasdaq 與所採行事曆的一致性。
- 根因：`scripts/analyze.py` 的 `_full_weeks` 只接受週一至週五都有資料的週，再檢查剩餘週是否相鄰。有假日的完整週因此中斷連續性。輸出有揭露改採日線，單看格式無法發現已知行事曆資訊沒有被用來區分休市和缺資料。
- 修正方向：結合已核實的交易日曆判斷週是否完整，區分休市、缺資料與當週未完結。不能證明時保留日線退回，並寫出具體原因。

### 4. 價位正文與改判條件使用不同精度（低，呈現）

- 日文筆記及原生報告將短期支撐列為 `325.0829909815337`，改判條件則顯示 `325.083`。盲審確認兩者源於同一 11/03 低點。機器驗證的原始數值正確，讀者看到的精度不一致。
- 位置與修正方向：`scripts/report.py` 的價位呈現與 `scripts/analyze.py` 的 `_conditions`。保留快照精度，統一報告的顯示精度。

### 5. 首次使用者要自行補上換版本或換輸入格式的規則（低，首次使用）

- 首次閱讀者指出抓價範例指定 `uv` 的 Python 3.12，報告改用 `python3`，若系統 Python 低於 3.11，前一步成功也無法保證能執行後一步。本機 Python 3.12.11，未重現版本失敗。
- 該閱讀者也無法從指引確定只有日期的歷史請求應如何取得精確時點，或何種擷取紀錄足以印證版本。CSV 未列為支援格式，這是輸入邊界需要清楚呈現。
- 位置與修正方向：`SKILL.md:19–27、47–77`。給最小完整快照範例，示範如何處理缺少時刻和時區的日期，並使報告使用已驗證的 Python。
