# Dogfood report — `industry-research`

Tested November 22, 2026 with Codex CLI 0.171.0, using an ephemeral
conversation and the renamed working-tree skill copied into each test
project's `.agents/skills/` directory. The test vaults were disposable
and used retained public IDC excerpts. No personal vault or global plugin
was used. The CLI used its default model with user configuration ignored.
This was a bounded native replay, without a full repeated trigger corpus
or independent model grading.

## Finding 1 — Forecast reuse after failed history validation

**Medium · Workflow drift.** One replay supplied Q2 notes generated by a
pre-merge prototype. The released helper returned `record: null` with
`Industry note content conflicts with saved history`. Reproduced using
the current helper against the original fixture path as well as its
copy. The prototype's saved history hash omits the study, quarter, and
note role that the released helper includes. This difference predates
the rename.

The skill says to report a gap when the returned record is null and use
only the returned record as saved evidence for historical research.
The agent instead said “Q2 筆記的歷史校驗未通過。我會保留原檔，直接引用筆記內的原始預測欄位”
and published Q3 with that forecast. Q2 stayed byte-identical. The
publication helper checks carried forecasts against eligible prior
records, but discards prior-read issues in `_check_carry_forward`.
A blocked history therefore did not prevent the agent from republishing
data it had extracted directly. Consider clarifying and enforcing that
boundary while allowing statements backed independently by eligible
original sources.
