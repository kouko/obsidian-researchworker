# AAPL Q2 研究更新判斷範例 v1

後續 agent 需要讀取檔案內容、依賴來源及工作狀態，才能決定要補資料、重評或新增一期。修改時間只用來找可能變動的檔案，不能證明研究已完成或資訊仍有效。本文件是待實作的設計範例，沒有排程、鎖定或自動執行功能。

## 要保存的最小資訊

| 資訊 | 用途 | 本例 |
|---|---|---|
| 標的及財季 | 判斷研究屬於哪一期 | Apple、2024Q2 |
| 分析模式與資訊截止日 | 分開固定歷史重建及最新判斷 | 歷史重建、2024-05-03 日末 |
| 分析版本與方法版本 | 知道哪種方法產生哪次結果 | q2-forecast-supplement-v1 |
| 來源版本、公布時間及相關欄位指紋 | 發現真正影響分析的改變 | 財報 accession、價格日期、輸入摘要 |
| 依賴與影響的筆記 | 避免只重寫一份卻留下不一致結論 | 預測改變後重評估值與綜合分析 |
| 各面向完成狀態及缺口 | 分開已有檔案與有足夠證據 | 外部共識仍缺失 |
| 工作身分、執行中狀態及已驗證輸出 | 中斷後續作，避免兩個 agent 重複寫入 | 本例沒有實際執行者，欄位為空 |

「指紋」是把選定的輸入內容轉成可比較的摘要。來源原始檔案的完整指紋另留作追溯；判斷分析要不要重做時，比較實際讀取的數值與身分欄位，排除下載時間、當前報價附帶資訊及排版。例如歷史收盤價相同，只是今天重新下載，不代表需要更新估值。

[research-state.json](research-state.json)是具體範例，並非已定版的通用格式。JSON 檔案的存在不代表程式已會判斷更新，也不能以單一 analysis_complete 值掩蓋某個面向仍缺資料。

## 常見變動如何處理

| 觀察到的變動 | 應採取的動作 | 保留的邊界 |
|---|---|---|
| 只碰觸檔案、修改時間改變 | 不重做分析 | 比較內容及依賴版本 |
| 重新下載但相關數值相同 | 記錄擷取嘗試，不改分析結果 | 擷取時間不等於證據時間 |
| 新找到截止日前已公布的展望 | 同季新增研究修訂版 | 記錄現在才發現，保留舊版 |
| 固定歷史分析收到截止日後價格 | 排除於該歷史版本 | 不把日期自動往後移 |
| 最新分析收到新價格、尚無新季報 | 同一財季新增市場與綜合分析版本 | 不建立假的新財季 |
| 最新分析收到新的合格財季財報 | 建立新一期研究 | 財季身分取自來源，不靠發布月份推算 |
| 晚於歷史截止日才發布修訂財報 | 記錄後來修訂，保留原當期判斷 | 不回填成當時已知 |
| 最新模式收到合格修訂且獲利改變 | 重做受影響的財務、預測、估值與綜合分析 | 未改變的其他面向可沿用並註明依據 |
| 共識資料取不到 | 留下缺口，繼續不依賴它的工作 | 不用零值或捏造預測補齊 |
| 來源無法核對公布時間 | 暫不納入固定歷史判斷 | 現在抓得到不代表當時已公布 |
| 方法改變但來源不變 | 新增方法修訂版及受影響結果 | 不是只有資料改變才需重評 |
| 中途停止，部分輸出已保存 | 檢查依賴和輸出指紋後續作 | 同名檔案不等於有效完成點 |
| 續作前依賴改變 | 使受影響的完成點失效並重算 | 不沿用舊預測配新資料 |
| 同一工作已有有效的執行者 | 避免重複寫入 | 鎖定、逾時及失效處理仍需實作驗證 |

全部範例另存 [update-examples.json](update-examples.json)。它們是預期行為，不是更新程式的測試執行紀錄。

## 財季與版本不能混用

Q2 分析可以預測 Q3，但在 Q3 財報公布前，不代表 Q3 財務分析已完成。對歷史 Q2 的日後新發現也只會增加 Q2 的研究版本；來源經濟時間、發布時間及本次撰寫時間需要分開保存。固定歷史重建與持續追蹤最新狀況應是明確模式，agent 不可暗中切換。

本例的初始資料範圍固定在 2024-05-03。後續事件及 Q3 財報在範例表中只描述應如何處理，不參與 Q2 的預測計算。

## 檔案能自動判斷到哪裡

可以固定保存來源身分、欄位依賴、缺口、方法版本和已驗證輸出，讓 agent 下次接續有依據。來源語意是否影響投資論點、產品毛利率落差是否合理、證據是否足以支持評級，仍需要分析與檢查，不能由修改時間或必填欄位數量決定。

未來程式還需處理可靠寫入、輸出提交完整性、重複工作、執行者失效、重試上限及依賴變更。這些屬於下一個軟體變更的範圍，本批沒有實作或宣稱通過。
