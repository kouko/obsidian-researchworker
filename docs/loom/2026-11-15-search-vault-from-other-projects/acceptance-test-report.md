## 對你既有的資料做了什麼 (what this did to data you already had)

這次改動不會寫入你的筆記庫：測試前後，你真正的筆記庫只有你自己今天寫的 2 篇新筆記和 Obsidian 自己重寫的工作區檔，多出的部分跟本測試無關；兩個測試筆記庫位元組完全一樣。它也不會改你的全域設定——我全程只用暫存的設定檔，前後比對過雜湊。但要注意，你讀過的筆記內容會跟其他檔案一樣送到模型服務。

## I decided for you

- **用暫存設定檔模擬「已完成一次性設定」**：我沒有改你的全域設定，而是把規則加進暫存設定檔；為了隔離「規則配不配得上命令」這個問題，我同時用了文件裡的原句和命令原本的長相兩種寫法。改天要在真實環境驗證，就得在你自己的設定裡加上那一行。
- **變數展開問題**：技能文件教的 `Bash(${CLAUDE_SKILL_DIR}/scripts/vault.sh *)` 規則在 headless/預設權限模式下永遠無法展開變數；把規則改成命令原本的長相 `Bash(sh /path/vault.sh *)` 確實能讓搜尋第一次直接執行，但那個長相在設定檔裡不會自動展開。這雙向問題（文件寫的長相 vs 設定檔展開行為）導致第 6 條始終差一行；把「搜尋指令」那一行一起寫進技能的一次性設定說明裡，讓「設一次之後不再問」真的做得到。
- **「哪些筆記連到 X」**：規格說要用 Obsidian 自己的連結資料，技能裡卻沒有這一步；agent 還會問你要不要幫筆記加回鏈。要不要補上這一步（Obsidian 開著時用它的 CLI，關著時直說做不到），並明令禁止提供任何寫入。
- **機器上完全沒有筆記庫時，開工提示列照設計保持安靜，而 agent 也不會自己呼叫技能，那句教使用者怎麼辦的原話等於說不出來**。要不要讓開工提示列在找不到筆記庫時也給一句提示。
- **派研究子 agent 時，主 agent 這次自己改用一般搜尋命令，沒有用技能裡那段可以直接貼上的指示文字**。要不要把那段文字改成預設必須照抄。
