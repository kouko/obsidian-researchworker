# Isolated finance research skill evaluation

The fixed all-criteria case metric improved from 6/9 to 9/9 trial runs
(66.7% to 100%, +33.3 percentage points). The separate fixed assertion metric
improved from 37/42 to 42/42 (88.1% to 100%, +11.9 points). Step 0's 15-point
gate applies to complete cases satisfying every criterion; it passes on that
definition. The assertion improvement is below 15 points and is not described
otherwise. There are three distinct synthetic scenarios, repeated three times
per configuration, not nine independent real research situations.

| Scenario | Baseline complete cases | With skill complete cases | Baseline assertions | With skill assertions |
|---|---:|---:|---:|---:|
| Missing research / unavailable market | 0/3 | 3/3 | 13/18 | 18/18 |
| Unchanged local evidence | 3/3 | 3/3 | 12/12 | 12/12 |
| Interrupted run / user edit | 3/3 | 3/3 | 12/12 | 12/12 |
| Total | 6/9 | 9/9 | 37/42 | 42/42 |

## What changed in observed behavior

Missing-work baseline 1 wrote a substantive standalone partial note without a
managed checkpoint or frozen method dependency. Baseline 2 published a checkpoint
but saved no completed units. Baseline 3 saved a reusable business unit and
method but did not explicitly distinguish the conflicting horizon conventions.
With the v1 skill all three persisted the independent excerpt-scoped business
answer, froze actual 2026 method authorship separately from 2024 economic input,
kept market/valuation/synthesis pending and explained the horizon distinction.
All supplied-section citations, actual reading exclusions and conditional
counterevidence are retained in the run artifacts.

No-op and conflict cases were already saturated without the skill. Both
configurations excluded future price evidence, bounded no-work to local scope,
kept external freshness unverified and refused conflicting recovery while
preserving user edits. Those cases validate retained boundaries here; they do
not establish an incremental benefit. SHA256 audits found every original file
unchanged in all 18 runs; no-op/conflict roots acquired no new files.

## Failures, improvement and rerun

Final outcome passes are not error-free execution. In `missing-skill-1` and
`missing-skill-3`, v1 agents supplied a list for `research.changes`; the helper
raised `ValueError: incomplete research envelope`. Both retained the failed
requests and eventually saved valid checkpoints. Run 1 safely abandoned its
old proposal before a distinct review. Run 3 used another run ID with the same
review target: a later target file must not be attributed to the first run.
The retained request digests/field values and `completion_run` bindings expose
that distinction. The owning task's
[mechanical boundary record](../../../research/04-publication-run-identity.md)
tracks it for integration repair; it was not repaired or counted as skill benefit.

The observed schema ambiguity led to v2's exact envelope types. The observed
failed-target pattern led to explicit safe-abandonment/new-review-ID guidance.
This is a targeted self-assessment inline repair, not a ceremonial rewrite or
a replacement of failed evidence. One fresh affected-case rerun used the same
fixture, task, frozen helper and evaluated README, differing in v2 skill guidance:
6/6 assertions, one successful publication, no ValueError/OSError and zero
changed originals. See [retained rerun](../inline-repair/runs/missing-skill-rerun.json)
and [grading](../inline-repair/grading.json). Its result does not inflate the
18-run matched comparison or prove that the broader mechanical gap is fixed.

One separate [unrelated diary smoke](../unrelated-note-smoke.json) read only the
diary and wrote its summary without invoking finance research. This is a single
negative routing observation, not automatic-trigger accuracy certification.

## Reproduction and limits

See [invocation](../invocation.md), [fixed cases](../cases.md), their per-case
metadata/gradings and [benchmark.json](benchmark.json). Inputs are reproducible
through the one-off fixture generator and frozen helper test fixtures. A
programmatic audit verifies matched initial hashes, nonempty outputs and
unchanged originals; semantic grading is author assessment, not closing review.
No permanent instruction-mirror tests or new evaluation framework were added.

The installed `scripts/aggregate_benchmark.py` was inspected and contains Markdown
usage prose rather than executable Python. The documented manual JSON schema
was used with actual grading data and standard-library arithmetic instead of
pretending that placeholder ran. The schema's unweighted mean of per-run
assertion fractions is 90.7% versus 100%; this is separate from both the primary
all-criteria case metric and the pooled 37/42 assertion count above.

No native duration/token fields were returned; those metrics are null. There
is no latency, dollar-cost or general efficacy claim. All agents were native,
fresh-context, sequential and inherited their model/effort. No external CLI,
private upload, installation, network request or new paid provider obligation
was used. These are fictional teaching mechanics, not real investment research,
real fresh-host continuation, blind forecast validation or independent acceptance.
Source-cache and stacked-delivery limitations remain unchanged.
The business-unit outcome is limited to the supplied synthetic excerpt question;
it does not validate complete business, accounting, governance or valuation
research. Real asset configuration must state the required question coverage;
a bare question ID and selected excerpts cannot certify that broader coverage.
All three scenarios use the same synthetic AAPL namespace; they do not establish
cross-issuer, cross-industry or non-equity capability. The skill's generic method
refuses unsuitable model transfer; that instruction still needs broader runtime
validation.

Repository HEAD advanced to `628e9cf` only for the parent's independent research
documentation; the helper/assessor hashes and evaluated README remained fixed.
The README overview/schema clarification was updated only after comparison and
inline rerun, so it is not an extra baseline/with-skill treatment difference.
