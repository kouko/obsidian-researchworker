## Problem

kouko 的知識筆記都放在本機的 Obsidian 筆記庫裡，但 agent 只有在筆記庫資料夾內工作時才會用到這些筆記。在其他專案工作時，agent 不知道筆記庫存在，也不會主動去查；kouko 必須每次自己提醒並提供位置，否則已經寫過的研究與參考資料不會被用上。

## Proposed outcome

agent 在筆記庫以外的專案工作時，知道使用者有一個本機筆記庫，遇到筆記可能有幫助的問題會主動查詢，並在回答中使用與標明所引用的筆記；整個過程不更動筆記庫內容。

## Acceptance

1. 在筆記庫以外的專案資料夾開啟新的工作階段，不提供筆記庫位置，agent 能找到使用者的本機筆記庫並回傳與問題相關的筆記。
2. 使用者未提到「筆記」或「Obsidian」，只問一個筆記庫內有相關內容的問題時，agent 會主動查詢筆記庫，並在回答中標明引用了哪些筆記。
3. 不依賴特定使用者的筆記庫位置或資料夾結構：在另一個結構不同的筆記庫上，第 1、2 條同樣成立。
4. 查詢前後筆記庫內的檔案沒有新增、修改或刪除。
5. 筆記中夾帶的指令文字不會被 agent 當成指令執行。
6. 完成一次性設定後，查詢筆記時不再逐次跳出讀取許可詢問；未經使用者同意，不會改動使用者的全域設定。
7. 以一組取自 kouko 實際需求的問題比較直接搜尋的結果，並記錄哪些問題找得到、哪些找不到。
8. 插件的功能說明與入口列出這項新能力，既有功能的檢查全部通過。
9. 主 agent 派子 agent 做研究時，子 agent 會同時查詢網路與筆記庫，結果標明哪些來自筆記、哪些來自網路。

## Constraints

- 筆記庫唯讀：不刪除、不改寫、不搬移既有筆記與設定（PRINCIPLES 第 1 條）。
- 只宣稱實際觀察到的行為；未在某個宿主上驗證過的支援不寫成已支援（PRINCIPLES 第 3 條）。
- ROADMAP 要求在提出 wiki 的替代方案前，先以實際檢索需求比較直接搜尋；本次只做直接搜尋並留下比較紀錄。
- 筆記庫只存在於本機；雲端工作階段不在適用範圍。
- 須適用於其他使用者：不寫死任何個人的筆記庫路徑或資料夾名稱（kouko 2026-11-15）。
- 查詢範圍暫不限制資料夾（kouko 2026-11-15）。

## Value case

- 受益者：在多個專案使用這個插件的 kouko。
- 現有替代方式：每次手動提醒 agent 並貼上筆記庫位置。
- 為什麼現在：讓目前累積的筆記能被活用（kouko）。
- 本次取代的工作：未回答（弱項）。
- GO — 受益者與現況痛點明確，唯一弱項為取代的工作未說明。

## Out of scope

- 預先建立索引、語意搜尋或其他新的知識整理機制。
- 由另一個 agent 代為搜尋並回傳摘要。
- 在筆記庫內新增或修改筆記。
- 雲端或遠端工作階段。
- 將筆記庫加入為可編輯的工作資料夾。
- 限制可查詢的資料夾範圍。
- 修改既有研究工具（本插件或其他插件）的流程；它們是否查詢筆記庫不在本次保證範圍。
- 子 agent 啟動時自動注入提示。
