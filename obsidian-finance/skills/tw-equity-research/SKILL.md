# 台股公司季度研究

在使用者指定的研究資料夾接續台灣證券交易所上市公司的研究。保留使用者的編輯及可回查的財務資料。單純找股價、下載資料或研究其他市場時，依該請求另行處理。

## 確定公司、期間與截至時間

以證交所或公司公布的資料核對代號、公司名稱及公司財務期間。上市公司識別碼用 `twse-<四位股票代號>`，例如 `twse-1611`。公司、期間或資料夾不明時，只詢問會影響研究範圍的資訊。未獲准建立的研究資料夾先不寫入。支援台灣上市公司。遇到上櫃公司，告知目前的適用範圍。

歷史研究使用帶時區的明確截至時間。只採用當時已公開且版本可驗證的資料。使用者要重看早於已儲存研究的時間時，保留現有報告，從本機已保存的證據唯讀回查。證據不足時指出缺口。需要另存時，使用已授權的隔離資料夾。沒有指定歷史時間且要看最新情況時，取數完成後以回傳的截至時間為準。

先讀已標示的研究總覽、公司入口、季度資料及既有分析。從本技能所在處解析共用 [Obsidian 資料契約](../../README.md#fixed-quarterly-notes)及 `../../scripts/research_store.py`。用 `research_store.discover(root, mode, cutoff, candidate_for=(asset_id, quarter), storage="quarterly")` 取得可重用結果、缺口、使用者新增的筆記及待處理項目。先讀已採用的主張目前在筆記中是否仍成立，並核對綁定的原始資料，才重用分析。一般使用者筆記可直接編輯。若某筆記自本次讀取後已變動，保留其內容，回報衝突並重新讀取後再接續。

## 取得與查核本次需要的資料

從本技能目錄解析指令路徑。先在暫存工作資料夾取資料及保留執行輸出，不直接把下載結果寫進已存報告。

```sh
python3 scripts/acquire.py 1611 2025Q3 --cutoff '2025-11-30T23:59:59+08:00' \
  --output '<暫存證據目錄>' --monthly-history '<已核對的歷史月營收 JSON>'
```

最新研究用 `--latest` 取代 `--cutoff`。需要完成年度研究時加 `--annual-year <財報年度>`。歷史月營收可先從公開資訊觀測站、公司投資人關係頁或公司原始新聞稿回查。傳入的 JSON 陣列每筆含 `ticker`、`month`（YYYY-MM）、`amount_ntd_thousands`（單位為新台幣千元）、`scope`、`available_at`、`url` 與可核對數字的原文 `payload`。日期未證實或原版本無法取得時，照實記錄缺口。最新模式中的 `observed` 是查詢時確認的版本，引用時用 `observed_at` 標示最遲當時可見，並註明來源未提供原發布時間。再接續研究可以重用已保存且符合截至日的版本。

- **季報與年報**：核對版本、發布時間、合併或個別口徑、期間、幣別及單位。財務實績優先引用原始財報或公司的官方量化揭露；當官方結構化資料可用時，用來核對數字。需要解讀 PDF 時，直接讀引用所需頁面的文字、圖或圖片表格。圖片數字要回看原頁的列、欄、單位和數值，註明頁碼及無法可靠辨識的欄位。季報更正後，使用截至日前已證實發布的更正版本；若取得程式只看到更正標記，先回查公司或官方發布的確切版本及日期，找不到則列缺口。
- **重大訊息**：從當季第一天查到研究截至時間。先區分查詢成功且查無公告、查詢失敗及已列出但本文未取得。讀取當季適用公告的本文；季後公告只採用與當季相關者。逐則核對季後項目，記錄納入或排除的依據；無法核對關聯時須保持待補。對有關的公告查找附件。
- **補充資料**：在公開資訊觀測站及公司投資人關係頁查找法說會簡報、逐字稿和影音，以及股東會文件與重大訊息附件。記下在哪裡、何時、以什麼期間查找，區分找不到、取不到及截至日前尚未公開。可在已核對來源足以回答的地方繼續分析；依賴缺失資料的主張保留待補。

一次處理一場已核對屬於這一季的法說會。將已查得的原始網址和公開時間寫進暫存 JSON。每筆 `sources` 含 `kind`（`slides`、`transcript` 或 `recording`）、`url`、`available_at`（未知用 `null`）。每筆 `searches` 含 `place`、`status`（`checked` 或 `failed`），可附 `kinds` 縮小查找對象和查找網址。先核對同一場次，逐字稿、影音和簡報可能各自在不同時間公開。

```sh
python3 scripts/conference.py --ticker 1611 --quarter 2025Q3 \
  --cutoff '2025-11-30T23:59:59+08:00' --input '<場次 JSON>' --output '<暫存證據目錄>'
```

優先用公司公布的逐字稿或截至時間前已可取得的字幕。若能證實字幕公開時間，可用 `caption_available_at` 明確記錄。只有公開影音可取得時，使用本機已裝的 `yt-dlp`、`ffmpeg`、`yap`，或加上 `--whisper-model <既有本機模型檔>` 讓工具使用本機 Whisper。缺工具、公開影音無法存取或轉錄失敗時，保留原始網址與缺口，繼續可完成的工作。逐字稿是為了定位管理層的策略、展望與問答。引用預測時加上發言時間或頁碼，並標示為預期；有相關官方簡報或公告時，先對照其數字與假設。校對關鍵片段後才支持研究判斷。使用本機資料處理，不把私人筆記或假設交給外部服務，也不自行安裝轉錄工具。

## 整理當季變動與預測

月營收更新到當季原有筆記，注明已取得的月份。只比較採用相同期間、口徑、幣別且在可比實績前已發布保存的預測。上一季只有整季預測時，保留該預測與發布時間，並列已發布的月營收，註明沒有可比的月度預測。較晚的預測變更另記日期和原因。

把已取得的財報與公告讀過並確認適用性後，可用以下指令核對資料門檻。只有核對過正式季報數字後才傳入正式營收；季後公告用已審閱並記錄判定依據的零起算索引，可重複指定。年度研究加 `--annual`。

```sh
python3 scripts/workflow.py '<取數結果 JSON>' --filed-ntd-thousands 1180 \
  --reviewed-post-quarter 0
```

當三個月營收加總與正式季報不同時，在財務分析正文並列兩筆數字及來源。若原因仍未查明，明確標示。以口徑與期間可比的正式季報數字檢驗整季預測。更正發布後更新同一份筆記和受影響的判斷，並在筆記的帶日期修訂紀錄保留原值、原始來源及當時判斷。

依實際研究問題和證據決定要完成哪些分析。先釐清實績與營運原因，再把公司展望和其他假設用於預測，保留反證、適用期間及限制。估值採用可追溯的預測與交易資料；沒有可核對的依據時標示待補。

## 保存與接續

沿用 [共用筆記範本](../equity-research/templates/)的欄位、角色與版本契約。新資料夾需獲准，先用研究總覽和公司入口範本建立標示過的入口與實際要回答的問題。採用的資料按季度保存：原始證據或內容雜湊綁定的擷取檔放入 `cycles/<YYYYQq>/data/raw/`，來源登記放 `data/sources/`，方法與假設放 `data/analysis/`。用來源登記的 `content_ref` 或 `original_ref` 指向同季相對檔案，保留原始網址、確定的可得時間、版本、期間和檔案雜湊。記錄取得日與原始公開日，分開管理層預期與已發生的實績。機器逐字稿登記為衍生資料，連回原影音的發布時間、網址及音檔雜湊；另外記錄執行轉錄的時間。

每季的 00 季度研究總覽與各個分析角色直接放在季目錄。以中電為例，財務分析是 `2025Q3 1611 中電 - 01 財務分析.md`。排序依序為 00 季度研究總覽、01 財務分析、02 營運分析、03 產業與競爭、04 預測、05 估值與風險、06 技術分析及 99 投資綜合結論。回報已儲存的內容、待補的證據及受影響的分析。季報、三個月營收及成功查核的適用重大訊息本文是季度完成門檻。年度研究另需年報。已回查卻沒有適用公告時，記明查詢結果。

使用 `publication_snapshot(root)` 在開始分析時掌握現有檔案。新證據落入季目錄後，只把這次已知新增的來源或方法納入快照；遇到既有檔案改動或意外新增時先保留並重新評估。用共用契約建構本次的研究紀錄，為每項已驗證分析綁定確實使用的來源版本、預測、假設和計算輸入。將有變動的分析依共用範本組成提案，鍵使用 ASCII，例如 `financial-analysis.md`；提案路徑與正式筆記名稱由共用儲存程式轉換。若有前次研究，使用其紀錄的 ID；可用的舊分析保留原有來源綁定。

呼叫 `research_store.publish(root, asset_id, review, files, expected, run_id, complete=..., storage="quarterly", company_name=company_name, ticker=ticker, overview_title=overview_title)`。資料門檻通過且要求的研究已具體核對時才可宣告完成。缺證據時仍可保存有根據的部分；法說會、股東會文件及公告附件的缺口影響依賴它們的內容。更新時在 `research.changes` 說明原因，保存前一版主張供回查。若儲存中斷，使用 `research_store.recover_quarterly` 後再重新讀取。保存後用 `research_store.discover` 核對可重用與待補的工作，必要時用 `verify_quarter` 核對引用的原始資料。回報實際保存的檔案、資料截至時間及這次查核結果。
